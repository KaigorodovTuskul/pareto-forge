## Что такое Pareto Forge?

**Pareto Forge** — переносимый [Agent Skill](https://agentskills.io/specification), который помогает агентам сначала определить **правильную задачу**, а затем решить её с минимальной необходимой сложностью.

Он сочетает приоритизацию по Парето, критическую проверку допущений в духе *Grill Me* и принципы инженерного минимализма, близкие к *Ponytail*.

> **Какой наименьший набор действий действительно даст нужный результат — без отказа от обязательных требований?**

Skill не обучает LLM заново, не заменяет модель и не гарантирует, что в любой задаче именно 20% усилий дадут 80% результата.

## Зачем нужен Pareto Forge?

Обычный coding-агент может создать много кода и предложить сложную архитектуру, даже если для результата достаточно небольшого изменения.

- **Раздувание объёма:** агент реализует все пожелания вместо разделения требований на обязательные и второстепенные.
- **Усложнение:** добавляет сервисы, зависимости и абстракции без подтверждённой пользы.
- **Непроверенные решения:** выбирает первый правдоподобный подход, не проверив критические допущения.
- **Иллюзия завершения:** считает написанный код доказательством достижения результата.

Pareto Forge меняет последовательность принятия решений:

| Обычный подход | С Pareto Forge |
|---|---|
| Реализовать весь список | Найти минимальный достаточный объём |
| Измерять количество сделанного | Опираться на желаемый результат |
| Добавлять инструменты «на будущее» | Сначала переиспользовать и упростить |
| Сразу принять план | Попытаться опровергнуть ключевое допущение |
| Объявить выполнение | Проверить результат на практике |

### Разделение функций

**LLM** оценивает варианты, выявляет важные допущения, формулирует вопросы и выбирает подход. **Необязательные детерминированные скрипты** проверяют формат данных, зависимости задач, ограничения бюджета и структуру skill.

Такие проверки повышают воспроизводимость технических процедур, но **не гарантируют** правильность экономических оценок, рациональность каждого выбора или одинаковое поведение во всех агентах.

## Как он работает

| Этап | Основной вопрос |
|---|---|
| **01 · Outcome** | Что считаем успехом? Какие ограничения обязательны? |
| **02 · Leverage** | Какие немногие действия дадут наибольшую пользу? Что отложить? |
| **03 · Challenge** | Какое допущение может сделать выбранное решение ошибочным? |
| **04 · Minimize** | Что можно удалить, упростить или переиспользовать? |
| **05 · Verify** | Как доказать, что результат достигнут, и вовремя остановиться? |

### Три режима

| Режим | Когда использовать | Глубина |
|---|---|---|
| **Flash** | Простая обратимая задача | Решение → упрощение → проверка |
| **Focus** *(по умолчанию)* | Разработка функций, выбор приоритетов | Варианты, компромиссы, критические вопросы |
| **Deep** | Дорогие и труднообратимые решения | Подробный Grill, эксперимент, запись решения и откат |

Skill старается выбирать самый лёгкий безопасный режим. Режим можно указать явно.

## Быстрый старт

### Вариант A — установка через Skills CLI

Установи Pareto Forge из публичного репозитория GitHub:

```bash
npx skills add KaigorodovTuskul/pareto-forge --skill pareto-forge

# Для конкретных агентов
npx skills add KaigorodovTuskul/pareto-forge --skill pareto-forge -a claude-code -a cursor -a codex

# Для агентов, поддерживаемых текущей версией CLI
npx skills add KaigorodovTuskul/pareto-forge --skill pareto-forge --agent '*'
```

Установщик развивается отдельно: [Vercel Labs skills](https://github.com/vercel-labs/skills). Перед использованием стороннего установщика изучи его полномочия и исходники.

### Вариант B — без Node.js и интернета

Для автономного установщика нужен Python 3.9+ (сам Markdown-skill не требует Python):

```bash
python scripts/install.py --project /path/to/your/project

# Проверка действий без изменений файлов
python scripts/install.py --project /path/to/your/project --all --dry-run

# Явный выбор агентов
python scripts/install.py --project /path/to/your/project -a claude-code -a opencode
```

Выполняй эти команды **из корневой папки скачанного репозитория**. В PowerShell используй `py` вместо `python`, если это требуется системой.

Установщик не перезаписывает существующую папку skill без `--force`. Подробности в [матрице совместимости](../COMPATIBILITY.md).

### Как пользоваться

Попроси агента:

```text
Используй Pareto Forge в режиме focus.
Мне нужно выпустить минимальную полезную версию функции.
Определи критерий успеха, обязательные требования и
самые полезные действия. Назови то, что следует отложить.
Проверь ключевое допущение, реализуй и проверь решение.
```

Для архитектурной задачи:

```text
Pareto Forge, deep mode: проведи критический аудит архитектуры.
Найди допущения, которые действительно могут изменить решение.
Предложи более дешёвые альтернативы и проверяемый эксперимент.
```

У разных агентов могут быть свои slash-команды. **Текстовое обращение к skill — наиболее переносимый вариант.**

## Совместимость

Pareto Forge использует канонический `skills/pareto-forge/SKILL.md` и распространяется без дублирования логики для каждого агента.

Установка описана для Claude Code, Codex, Cursor, Gemini CLI, OpenCode, GitHub Copilot, Cline, Windsurf и ряда других клиентов. Но совместимость формата **не гарантирует**, что каждый агент правильно обнаружит и вызовет skill. Актуальные пути и ограничения: [docs/COMPATIBILITY.md](../COMPATIBILITY.md).

## Примеры

### Планирование релиза

Задача: команда должна за неделю выпустить рабочий сценарий онбординга, выбирая из 15 идей.

- **Результат:** надёжный процесс приглашения новых сотрудников.
- **Обязательные условия:** контроль доступа, аудит, доступность интерфейса и существующие API-контракты.
- **Минимальный пилот:** повторно использовать API приглашений и проверить критические пользовательские сценарии.
- **Отложить:** новый движок процессов, декоративные виджеты и спекулятивные интеграции.
- **Проверить:** сбои приглашений, пользователи нескольких команд, реальное выполнение требований.

Это **иллюстративный пример**, а не доказательство экономии 80% ресурсов. [Подробнее →](../../examples/release-planning.md)

### UI-компонент

Задача: добавить выбор даты. Агент сначала ищет существующий компонент и рассматривает стандартный `input type="date"`. Новая библиотека появляется только тогда, когда требования к UX, доступности или совместимости действительно этого требуют. [Подробнее →](../../examples/web-app.md)

## Необязательный калькулятор приоритетов

```bash
python skills/pareto-forge/scripts/rank.py --input examples/candidates.json --budget 6
```

Он использует эвристику `impact × confidence / effort`, учитывает обязательные задачи и зависимости. Баллы **не являются измеренной экономической выгодой**, а выбор по бюджету не претендует на математический оптимум.

## Benchmark Lab

Добавлен самостоятельный [`benchmark/`](../../benchmark/README.md) для **30 задач** (20 исполняемых и 10 экспертных), A/B или A/B/C сравнения с Vanilla и Ponytail, автоматических проверок, слепого парного оценивания и HTML-отчёта с графиками.

**Важно:** реальные LLM-бенчмарки пока не выполнены. Имитационный режим предназначен только для проверки инструментов и не подтверждает эффективность. Код, создаваемый агентом, нужно запускать в изолированной среде. Правила публикации результатов: [`PROTOCOL.md`](../../benchmark/PROTOCOL.md).

## Тестирование

```bash
python scripts/validate.py
python -m unittest discover -s tests -v
python -m unittest discover -s benchmark/tests -v
```

В репозитории есть структурные тесты, тесты Python-инструментов и сценарии для будущих сравнительных испытаний поведения LLM. **Независимых бенчмарков эффективности и доказанной экономии токенов пока нет.** См. [план оценки](../EVALUATION.md).
