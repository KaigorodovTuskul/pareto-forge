# Select the highest-return slice, not the fanciest plan

**Read only when there are real competing priorities.** For an obvious small task, skip this file and execute.

1. Identify the essential user outcome and the obligations that cannot be traded off.
2. Find the binding constraint (time, usability, availability, cost or correctness).
3. For at most 2–3 plausible paths, ask: which gets a usable result soonest, with least total cost?
4. Prefer a cheap reversible action over a lengthy decision meeting or speculative future-proofing.
5. Defer optional work. Revisit only if observed usefulness is insufficient.

If comparing a larger list with evidence, optional `scripts/rank.py` supports heuristic impact × confidence ÷ effort and dependency constraints. **Never** treat invented 1–5 scores as calibrated return on investment. No numerical ranking needed for a 5-minute action.

The core stop rule is **diminishing marginal value**, not a fixed quota of 20% tasks. If the user explicitly requires all features, the required 100% coverage is a hard constraint, not a number to optimize away. For ambiguous scope, ask once or label a reversible first slice as a proposal, not final completion.
